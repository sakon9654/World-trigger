# Border — หน้าจอ Operator, เรดาร์ และขอบเขตข้อมูลขณะแข่งขัน

## จุดตั้งต้น: ต้องแยกข้อมูล 3 ฝั่ง
1. **Operator ฝ่ายทีม** เช่น ลูน่า: มีข้อมูลจากเครื่องมือที่ได้รับอนุญาต เรดาร์ แผนที่สนาม สถานะพันธมิตร การรายงานจากสมาชิก และข้อมูลที่ตรวจยืนยันได้; ไม่ใช่ผู้บรรยายรอบรู้.
2. **เจ้าหน้าที่ผู้แข่งขันในสนาม** เช่น เร็น มิโอะ: เห็นสิ่งตรงหน้า รู้รายงานผ่านการสื่อสารและข้อมูล Overlay ที่ Operator ส่งให้; ไม่ได้รับภาพรวมครบทุกอย่างโดยอัตโนมัติ.
3. **ผู้ชม/ผู้บรรยาย Rank Wars และภาพที่ผู้เล่าเรื่องตัดไปเห็น:** อาจมีมุมกล้อง/ภาพรวมและข้อมูลมากกว่าฝ่ายทีม; **ห้ามนำสิ่งที่ผู้ชมรู้ไปเป็นสิ่งที่ Operator ฝ่ายทีมรู้โดยไม่มีแหล่งข้อมูล**.

## อ้างอิงต้นฉบับ — Border Briefing File และมังงาถึงตอน 196

### การช่วยเหลือใน BBF Q233 (ยืนยัน)
- Operator **ส่งข้อมูลแบบเรียลไทม์เข้าไปในมุมมองของเจ้าหน้าที่** ไม่ใช่แค่พูดวิทยุ: แท็กศัตรูที่ปรากฏบนเรดาร์, เส้นทางไปสมทบเพื่อนหรือถอย, แจ้งจุดเสี่ยงด้านข้าง/ด้านหลัง, แจ้งความเสี่ยงจาก Sniper, ทิศทางคาดการณ์การเคลื่อน, แผนยุทธวิธี ฯลฯ.
- จุดวัดฝีมือคือ **คัดเลือกข้อมูลให้พอดีและเข้าใจง่าย** ยิ่งเก่งยิ่งหลีกเลี่ยงยัดข้อมูลจนรบกวนการตัดสินใจในสนาม.
- แหล่งอ้างอิง BBF p.316 Q233: https://worldtrigger.fandom.com/wiki/Question_Corner/Databook และ https://worldtrigger.huijiwiki.com/wiki/边境相关Q%26A

### เรดาร์ (ยืนยัน + จุดจำกัด)
- เรดาร์จับ **สัญญาณ Trion ของร่างผู้ใช้ Trigger** เป็นจุดพร้อมทิศทาง/การเคลื่อนที่โดยประมาณ; อาจมีความสูงสัมพัทธ์เช่น HIGH/LOW แต่ **ไม่ได้ให้ภาพชัดว่ากำลังทำอะไรหรือเห็นใบหน้าคนคนนั้น**.
- Operator นำจุดเรดาร์ทาบกับแผนที่ภูมิประเทศ/ตำแหน่งอาคารและ **ใส่แท็กตัวตนตามหลักฐาน** (เช่น สมาชิกเห็นคู่ต่อสู้, ตำแหน่งก่อนหน้า, ปฏิกิริยาศัตรู). **จุดเรดาร์ที่เพิ่งพบไม่ได้มีชื่อคู่ต่อสู้แน่นอนอัตโนมัติ**.
- **Bagworm:** ปิดสัญญาณบนเรดาร์มาตรฐาน; หายจากจอ **ไม่เท่ากับหายจากสนาม**. จุดสุดท้ายที่เห็นเป็นเพียง *ตำแหน่งล่าสุดที่ยืนยัน* ไม่ใช่ตำแหน่งปัจจุบัน.
- **Chameleon:** ล่องหนต่อสายตาแต่ยังตรวจด้วยเรดาร์ปกติได้; อย่าเขียนว่าล่องหนทำให้จุดเรดาร์หายเหมือน Bagworm.
- การเพิ่มความละเอียดของเรดาร์อาจทำได้ แต่ต้อง **ใช้ Trion เพิ่ม**; ไม่ให้ฝ่าย Operator กดเพิ่มจนมองผ่าน Bagworm ได้โดยไม่มี Trigger/ความสามารถเฉพาะ.
- แม้มีจุดเรดาร์ก็ยังต้องดูอาคาร ชั้น มุมอับ และการยืนยันเพิ่ม; **ไม่ใช่เรดาร์สำหรับเล็งยิงศัตรูที่ไม่เห็นตรง ๆ อย่างแม่นยำ**.
- แหล่ง: https://worldtrigger.fandom.com/wiki/Radar ; https://w.atwiki.jp/worldtrigger2ch/pages/16.html ; BBF Q140 https://worldtrigger.fandom.com/wiki/Question_Corner/Databook

### การติดตามสถานะและการช่วยประสาทสัมผัส (รองรับ แต่ไม่กำหนดหน้าจอเป็นตัวเลขเกินหลักฐาน)
- Operator สามารถประสาน **สัญญาณสถานะของเพื่อนร่วมทีม / ความเสียหาย / การ Bail Out** ตามข้อมูลระบบและรายงาน; ควรบอกเป็น "แขนซ้ายเสียหาย", "สัญญาณ Trion รั่ว", "ขาดการเชื่อมต่อ", "Bail Out" ตามหลักฐานที่ได้รับ. **อย่าใส่แถบ HP มาตรฐานหรือเปอร์เซ็นต์ Trion แม่นยำของศัตรูทุกคนโดยอ้างว่า Canon**.
- Operator ช่วยปรับการมองเห็น แชร์ข้อมูลภาพ/การรับรู้เฉพาะกรณีที่มีการรองรับและจัดเตรียมไว้; **ไม่ใช่ CCTV สดทุกมุม ทุกตึก หรือเห็นผ่านตาศัตรูได้ตลอดเวลา**.
- เมื่อพันธมิตรยิงถูกคู่ต่อสู้ ระบบมีการแจ้งผลบางประเภท; **ไม่เท่ากับรู้ความเสียหายภายในของศัตรูครบทุกชิ้นเสมอ**.
- ข้อความเตือนเฉพาะ/เลย์เอาต์กราฟิกในฉากเขียนได้ แต่ให้ระบุเป็น **UI ที่เสนอสำหรับแฟนฟิก** ไม่ใช่ภาพหน้าจอ Canon ทุกพิกเซล.
- แหล่ง: https://worldtrigger.fandom.com/wiki/Operator ; https://worldtrigger.fandom.com/wiki/Trion_Body

### BBF Q235 — ขั้นพื้นฐานของ Operator
- ผู้เข้าใหม่โดยปกติฝึกเป็น **Central Operator** และเรียนรู้อุปกรณ์/งานสนับสนุนก่อนย้ายหรือได้รับเลือกให้เป็น Operator ประจำทีม.
- **ตอน 5 ของแฟนฟิก** ลูน่า "ผ่านการประเมิน" แล้ว แต่บทนั้นยังแยกขั้นตอนการยืนยันข้อมูลเข้าทีม; **อย่ารวบว่าการสอบผ่านครั้งเดียวเท่ากับข้ามทุกขั้นตอนงานพื้นฐานและได้สิทธิ์เปิดระบบทีมทุกอย่างทันที**. กรณีขั้นตอนเฉพาะของลูน่าที่ยังไม่เล่าให้เป็นช่องเปิด ไม่กำหนดชื่อระบบใหม่โดยพลการ.
- แหล่ง: https://worldtrigger.fandom.com/wiki/Question_Corner/Databook (Q235)

## หน้าจอสำหรับเขียนฉากลูน่า — แม่แบบเชิงปฏิบัติ (fanfic UI, ไม่ใช่ผังจอที่ Canon ล็อก)

| แผง/ข้อมูลที่ Operator อาจใช้ | เห็นอะไร | ข้อจำกัดในการเล่า |
|---|---|---|
| **แผนที่สนาม + เรดาร์** | เค้าโครงถนน อาคาร จุดสัญญาณ Trion ที่ตรวจได้, พิกัดล่าสุด, แท็กที่ยืนยัน | Bagworm ทำให้จุดหาย; ไม่เปิดชื่อทุกจุดอัตโนมัติ; อาคารทำให้ไม่รู้มุมยิงจริง |
| **สถานะฝ่ายเรา** | สมาชิกอยู่ที่ใดล่าสุด, สถานะสื่อสาร, ความเสียหายที่ระบบแจ้ง/สมาชิกยืนยัน | ไม่อ้างเปอร์เซ็นต์ HP/Trion เป็นมาตรฐานหากไม่มีหลักฐาน |
| **บันทึกข้อมูลและแท็ก** | เป้าหมายที่ระบุตัวตนแล้ว, แหล่งรายงาน, เวลาอัปเดตล่าสุด, ความเชื่อมั่น | "เห็นเมื่อกี้" ไม่เท่ากับ "ยังอยู่ที่นั่น" |
| **แผนเส้นทาง** | ทางรวมพล, ทางหนี, แนวป้องกัน, มุมเสี่ยง Sniper ที่ประเมินได้ | เส้นทางที่แสดงคือข้อเสนอ ไม่ใช่เส้นทางปลอดภัยแน่นอน |
| **การสื่อสารและแจ้งเตือน** | เสียงรายงานของทีม, คำสั่ง, การขาดสัญญาณ, สัญญาณเสียหาย/ผลการโจมตีที่ระบบแจ้ง | การขาดสัญญาณไม่บอกสาเหตุได้ทันที |
| **ข้อมูลภาพ/การรับรู้พิเศษ** | ภาพหรือการช่วยเล็งที่ส่งให้/แชร์จากพันธมิตรในกรณีรองรับ | ไม่ถือว่ามีภาพสดจากกล้องทุกตัว ทุกถนน ตลอดการแข่งขัน |

> **รูปแบบ 'แผง' ในตารางเป็นเครื่องมือจัดฉากของนิยาย ไม่อ้างว่าหน้าจอ Border มีเลย์เอาต์แบบนี้แน่ทุกจอ**.

## ระดับความแน่ใจในข้อมูล — ต้องใช้ในการบรรยาย
- **ยืนยัน**: เรดาร์ที่กำลังแสดงอยู่, สมาชิกเห็นเป้าหมายตรง ๆ, รายงานสถานะที่ได้รับ, ภาพซึ่งเข้าถึงได้จริง.
- **ตำแหน่งล่าสุด**: ศัตรูเคยอยู่ที่จุดนั้นก่อนหายไปจากเรดาร์ / เปิด Bagworm / เข้ามุมอับ; ไม่ใช่การติดตามสด.
- **คาดการณ์**: วิเคราะห์ทางหนี ลักษณะอาคาร เจตนาศัตรู หรือจุดที่น่าซุ่ม; ให้ลูน่าพูด "คาดว่า", "ยังไม่ยืนยัน", "มีความเสี่ยง" ไม่พูดเหมือนเห็นจริง.
- **ไม่ทราบ**: Sniper ที่ใช้ Bagworm และไม่เปิดเผยตำแหน่ง, ฝ่ายตรงข้ามในอาคาร/ห้องอับ, แผนในใจศัตรู, จำนวนกระสุนและ Trion คงเหลือของศัตรูอย่างแม่นยำ.

## กฎการสั่งการและการนำภาพไปใช้ในเรื่อง
1. ลูน่ารับข้อมูล → แยกยืนยัน/ตำแหน่งล่าสุด/คาดการณ์ → ตัดสิ่งไม่จำเป็น → ส่ง **คำสั่งสั้น ๆ ก่อน**, อธิบายเหตุผลตามเมื่อมีช่องว่าง.
2. เร็นอาจ **เห็นเป้าจริงก่อนจุดบนเรดาร์ได้รับการแท็ก**; ต้องรายงานให้ลูน่ากับมิโอะรู้, ไม่ใช่ให้ลูน่ารู้พร้อมเขาอัตโนมัติ.
3. มิโอะในฐานะ Sniper มีมุมมองจริงของเธอ เธอควรรายงาน "เห็น/ไม่เห็น/มีอะไรบัง" เพื่อให้ลูน่าเลือกเส้นทางหรือคุมจุด.
4. ลูน่าช่วยเร็นด้วยแผนที่และคำเตือนที่อธิบายที่มาได้ แต่ **ห้ามรู้ Side Effect 'Bullet Line' หรือเส้นทางกระสุนที่อยู่ในหัวเร็น** ก่อนจุดค้นพบในโครงเรื่อง.
5. ถ้าแสดงหน้าจอในเนื้อเรื่อง ให้เล่าแบบจำเพาะ "สัญลักษณ์ตรงทางแยกหายไป", "แท็กเปลี่ยนเป็นตำแหน่งสุดท้าย", "จอแจ้งสัญญาณ Trion รั่ว" ดีกว่าแสดงกราฟิกเกินจริงหรืออธิบายทุกช่องในทุกฉาก.
6. ภาพกล้อง/มุมผู้ชม/ผู้บรรยายเกม Rank Wars เป็นคนละสิทธิ์ข้อมูลกับจอทีม; **ตัวเลขระยะเป็นเมตร** ให้ผู้บรรยายเกมพูดในฉากพากย์ตามกฎภาษา ไม่ยัดใส่ร้อยแก้ว.
7. **ห้องฝึกแยกบุคคล:** Operator อยู่ที่จุดควบคุมที่ได้รับอนุญาต; มิโอะและเร็นอยู่ในห้องฝึกคนละห้อง. เมื่อจบจึงพบกันพื้นที่ส่วนรวม.
8. หน้าจอฝึกจำลอง **อาจจัดเตรียมข้อมูลตามโจทย์ฝึก** มากกว่าที่จะได้ใน Rank Wars; ถ้าลูน่ามีภาพหรือการแจ้งเตือนเฉพาะจาก 'ระบบจำลอง' ต้องระบุว่าเป็น **ข้อมูลของแบบฝึกนั้น** ไม่ยกไปถือว่าเห็นได้ตามปกติในการแข่งจริง.

## ตัวอย่างการเขียนที่ใช้ได้
> สัญลักษณ์สองจุดเคลื่อนเข้าหากันบนแผนที่ ลูน่าตรวจข้อมูลรายงานล่าสุด แต่จุดที่สามหายไปทันทีที่คู่ต่อสู้เปิด Bagworm เธอไม่ได้รู้ว่าอีกฝ่ายวิ่งไปทางไหน จึงทำเครื่องหมายตำแหน่งสุดท้ายไว้ แล้วส่งคำเตือนให้มิโอะระวังดาดฟ้าทางใต้.
>
> “มิโอะ จุดที่สามหายจากเรดาร์ ตำแหน่งล่าสุดอยู่หลังอาคารฝั่งใต้ ยังยืนยันการเคลื่อนไหวไม่ได้ อย่าเปิดตัว”
>
> “หนูรับทราบค่ะพี่”

## ข้อห้ามสำหรับการแต่งต่อ
- ห้ามลูน่ามองเห็นผู้ใช้ Bagworm บนเรดาร์มาตรฐาน, ระบุชื่อศัตรูทุกจุดโดยไม่มีหลักฐาน หรือเห็นทุกห้องจากจอเดียว.
- ห้ามให้ข้อมูลผู้บรรยายหรือภาพผู้ชมไหลไปเป็นข้อมูลลูน่าอย่างไม่มีแหล่ง.
- ห้ามอ้างว่าลูน่ามองเห็น HP/Trion ศัตรูเป็นตัวเลขแน่นอน, รู้แผนของฝ่ายตรงข้าม, รู้วิถีกระสุนทั้งหมดล่วงหน้า หรือรักษา Trion ที่ใช้ไปแล้ว.
- อย่าล็อกองค์ประกอบ UI เฉพาะของแฟนฟิกว่าเป็น Canon โดยไม่มีหลักฐาน.
